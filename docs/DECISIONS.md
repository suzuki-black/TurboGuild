# DECISIONS — 仮決め・仕様からの変更の記録（1 行 / 件）

1. **RAM 予算を 10KB → 静的 6KB に変更**。実測（openMSX FS-A1ST, FDD 1 台）で HIMEM=DE67h、C000h〜HIMEM は 7,783 B しかない。静的 RAM 6,144 B ＋ スタック約 1.6KB とし、`make` の表示も `RAM used: x / 6144`。実機で HIMEM がさらに低い場合は再調整。
2. CPU は仕様どおり `CHGCPU` に `81h`（R800 ROM モード + LED）。S1990 の直書きはしない。
3. 半角字形は ROM に持たず、本体 BIOS の `CGTABL`（0004h）を読む。半角カナもそのまま出せ、ROM を消費しない。
4. 仕様 §10 の `tools/demo_*.c` は作らず、ROM 内の Phase0 試験画面（BANK / CARD / SAVE・RTC / INPUT・SOUND）で代える。1 本の ROM で全部確認できるため。
5. `cards.csv` には名前を文字列のまま書き、`text_id` は `build_data.py` が振る。元データ（CSV・data/text）は UTF-8、`text.dat` は Shift-JIS(cp932) に変換して入れる。
6. セーブディスクのメディア ID は `F9h`（2DD 720KB）固定。turbo R の内蔵 FDD は 2DD のみのため、2HD 判定は実装しない。
7. Phase0 ではセーブディスク初期化の確認画面を省き、識別セクタが無いディスクには初回保存時に識別を書く。確認画面は Phase1 の UI で付ける。
8. ROM のページ 0 以外の先頭 16 バイトを「ページ見出し」`[page,'T','G','P',種別]` とし、中身は +10h から置く。バンク切替テストと取り違え検出のため。
9. INIT が 2 回呼ばれる（ASCII8 の初期バンクで 8000h にも "AB" が見える）ので、H.STKE が既に自分を指していれば黙って RET する。
10. ジョイスティックは BIOS `GTSTCK` でなく PSG R#14 を直接読む（キーボードのカーソルと混ざらないように）。
11. ~~`AP_MAX = 20`（仮）~~ → 企画書どおり `AP_MAX = 100`。回復は現実 5 分で 1、レベルアップで全回復。
12. 自動テストの機種は openMSX 同梱の `Panasonic_FS-A1ST`（FDD 付き実ファーム、システムROM が必要）と、非 turboR 確認用の `C-BIOS_MSX2_JP`。
13. ~~コードバンク 1 を窓 6000h に常駐~~ → #14 で置き換え。
14. **コードバンクは「バンク n の領域 `_BANKn` を 24bit 番地 0xn6010 にリンク」し、別バンクの関数は `FAR(...)` で定義してカーネルの中継（`tools/gen_far.py` が生成）経由で呼ぶ**。仕様 §2.3 の `bank_call(bank, fn, arg)` の代わり。呼ぶ側は普通の関数呼び出しで書け、引数の型も C のまま検査される。制約は「引数はレジスタで渡る組み合わせだけ（u8/16bit を同じ幅で 2 個まで）」と「別バンクの const へのポインタを渡さない」。SDCC は別バンクの関数を直接呼んでもリンクを通してしまうので、`tools/check_banks.py` がリンク後に検査して止める。
15. 漢字ROM の番地: 非漢字は `(区+20h-20h)*96+(点+20h-20h)`、漢字は `1024+(上位-30h)*96+(下位-20h)`、字形は 8x8 の 4 ブロック（左上・右上・左下・右下）。実ROM の字形を描いて確認した。漢字ROM は JIS 第1水準だけなので、`build_data.py` が第2水準の字を弾く（嵐呼びの巫女→神子、翡翠→緑玉、終焉→終末 に替えた）。
16. 画面の文言はすべて `data/text/ui.txt`（キー<TAB>文字列）に置き、C には `T_*` の id だけを書く（仕様 §11）。文字列は Shift-JIS で `text0.dat` 以降のページに入り、先頭の目次で引く。
17. 1 行は 16 ドット（13 行）。全角は漢字ROM の 16x16、半角は BIOS 字形を縦 2 倍にした 8x16。8x8 の字は Phase0 の診断画面だけ。
18. 自分の HP = 200 + 20×Lv（仮）。仕様 §6 の player_hp が未定義だったため。
19. 敵の攻撃 = 30 × ステージ番号（仮, `stages_rule.csv` の atk_mul）。仕様 §4.2 に enemy_atk の式が無かったため。
20. 次のレベルまでの経験値 = 50 + 2×Lv²（仮）、上限 Lv150（u16 に収めるため）。最初の 1 + 20×Lv だと 5 分で Lv29 になり、レベルアップの AP 全回復で AP が意味を失った。調整は Phase3 の `sim_economy.py` で。
21. デッキのコスト上限 = 30 + 2×Lv（仮）。おまかせ編成は「入る中で攻撃最大」を 5 回選ぶ貪欲法。
22. ドロップは「エリアの属性 × 通常 N / ボス R」の恒常カードから等確率。`areas.csv` の boss_card_id はボスの名前に使うだけで、落とさない。
23. 初期資産は G 3000・石 3000（仮）。最初の 10 連はプレミアの確率＋SR 以上 1 枚確定で、何度でも引き直せる。引き直しで天井カウンタが貯まらないよう 0 に戻す。
24. 負けても AP は減る（当時風）。報酬・ドロップ・進行は勝ったときだけ。
25. 保存は「変更があれば HOME に戻ったとき自動で（「通信中…」表示）」＋ HOME の「セーブ」。ディスクが無ければ一度だけ知らせて続行。
26. ガチャチケットは「チケットガチャ」（ゴールドと同じ確率）、SR 確定チケットは「SR95%/SSR5%」のガチャとして `gacha.csv` に足した。イベントガチャ（id 4）はイベントが始まる Phase2 まで一覧に出さない。
27. 所持カードが 200 枚で満杯なら、ガチャは引かせず、ドロップは「受け取れなかった」と出す。売却・合成は Phase2。
28. 自動テスト用に RAM に 2 バイト（`g_test_keys`: 1 フレームだけ押したことにするボタン、`g_ui_state`: 描画中/待機/押下待ち）を残す。製品版でも害がなく、実機でも同じ ROM を検証できるため外さない。
29. タイトルで ESC を押すと Phase0 の診断画面（バンク試験・カード表・セーブ/RTC・入力）に入れる。
30. `rng.c` `time.c` はハード非依存（core/）だが、どのバンクからも呼ぶのでカーネルに置く。`save.c` はセーブ管理と同じ UI_START バンク。
31. **画面を「絵が主役」に作り直した**（2026-10-19 のユーザー指示）。当時の携帯ソシャゲの UI/UX（十字キー＋決定、数字キーで直接選ぶ、色反転の選択、マイページ中心、Flash の演出、決定を押したら見ているだけの自動戦闘）を MSX に置き換える。絵はすべて手続きで生成（`tools/art/`, `tools/gen_art.py`, 開発時のみ Pillow が要る）。画面部品は 256x256 のアトラスにして起動時に VRAM ページ 1 へ読み込み、VDP のコピー命令（HMMM / 透過の LMMM）で貼る。カード絵（56x72）と小さい絵（28x36）は ROM から CPU で直接描き、詳細・ガチャ・ボスでは 2 倍に広げる。ROM は 512KB に広げた。
32. **クエストは「進む」を押して探索度を 100% にする遊び**にした。仕様の 500 ステージ（1 エリア 10 ステージ）をそのまま使い、「進む」1 回 = 1 ステージ、探索度 = エリア内の進み × 10%。10 ステージ目はボス戦の画面（ボスのカード絵を 2 倍、デッキが順に攻撃、HP ゲージ、被弾で画面が揺れる）。クリア済みエリアは 1 から周回する。
33. **軍資金（リアルマネーの代わりに一人ひとりが持つお財布）を足した**（2026-10-19 のユーザー指示。仕様 §12 の「リアルマネー要素なし」を変更。実際のお金は一切扱わない）。軍資金で石を買い（1 石 = 1 円、パックは `data/gem_packs.csv`）、石でプレミアガチャ・回復薬を買う。新規開始時にお財布のコースを選ぶ（`data/courses.csv`: おこづかい・社会人・石油王・無敵モード）。ゲーム内 30 日ごとに給料（コースの月額）が入り、何か月空いても溜まる。無敵モードは軍資金が減らない。累計課金額を記録して見せる。
34. 携帯の数字キー操作を再現: マイページは 1〜8、ガチャは 1〜5、ショップ 1〜3、デッキ 1〜6、お財布 1〜4 で直接選べる（各ボタンに数字キーの絵）。メニュー名は 64 ドットの枠に収まる長さにした（冒険・お店・保存・終了）。
35. パレットは絵の生成と共通の 16 色（`tools/art/palette.py`）。C の COL_* はその番号。
36. SDCC の警告 158（定数＋定数が 127 を超えて u8 引数に渡ると出る誤検知。生成コードは正しい値）と 110（最適化の通知）を止めた。
37. マイページの最下段はお知らせを右から左へ流す（携帯サイトのマーキー）。ログインボーナスは 7 マスのスタンプカードで、今日の分を押す演出つき。
38. 敵の名前を属性ごとの絵（トカゲ・スライム・ハチ・ゴーレム・獣）に合わせて付け直した（絵と名前の食い違いを無くすため）。
39. 保存中は UI 状態を「処理中」にする。自動試験が書き込みの途中でリセットして古い方のスロットを読んでいた（ゲームの不具合ではないが、実機で途中で電源を切った場合も A/B の古い方から読める）。
40. 所持カードに合成経験値の欄を足した（1 枚 6 バイト。200 枚で 1.2KB、セーブは 2KB 枠の中）。仕様 §5 の `{u16 id; u8 lv; u8 flags}` に `u16 exp` を追加。
41. 進化先のカード（`祭りの舞姫＋` など）は `event_id = 65535` にして、ガチャ・ドロップのプールに入らないようにした（進化でしか手に入らない）。ひよこ剣士・泉のうさぎも進化できるようにした。
42. イベントの開催日は `events.csv` の `start_day`（ゲーム内日数）で決める。Phase3 で運営年表（timeline.csv）の EVENT 行から始めるように置き換える。第 1 回「星降る夏祭り」は 3 日目から 14 日間。
43. イベント kind=0（周回ボス型）の面は `event_stages.csv` の 初級・中級・上級 の 3 つ。クエストの `quest_run(EVENT_STAGE_BASE + 面)` で戦い、イベントの分岐は quest.c の setup() の 1 か所（仕様 §4.4）。特効カードは攻撃 ×5、進化後は ×20。
44. 報酬は `event_rewards.csv`。ポイント報酬（届いたら 1 回だけ自動で受け取る。受け取り済みは `event_rewards_claimed` のビット、最大 8 本）と、最終順位の報酬（順位がしきい値以下の最初の行）。報酬の種類に「カード」を足した（amount = カード id）。
45. 参加と終了は、マイページに入るたびに `event_update` で判定する。「参加中の id ≠ 開催中の id」なら終了とみなして最終順位と順位報酬を配る。何日空けて起動しても同じ（期間をまたいだセーブを読み込んでも終了処理が走る）。終わったイベントは `last_event` に残し、同じイベントに入り直さない。
46. NPC 1000 人（`tools/gen_npc.py`, 種固定）は Phase2 では静的データ。イベントポイントは「最終値 × 開催の経過割合」で全員同じ倍率で伸ばすので、並びが崩れず順位は二分探索で数える。総戦力は固定値で、総戦力順の添字表を別に持つ。名前は当時の携帯 SNS 風のハンドル名（前半 20 × 後半 50）にして実在の人物と重ならないようにした。
47. マイページのメニュー 6 は「ログボ」から「ランク」に替えた（ログインスタンプはボーナスが出るときに自動で開く）。開催中はバナーがイベントの入口になり、[9] か上キーで選べる。イベント開催中はガチャにイベントガチャ（限定カード 2 倍）が加わる。
48. 自動試験用に RAM に 1 バイト（`g_test_digit`: 数字キーを押したことにする）を足した。SaveData の欄の位置は `tests/save_offsets.c` が offsetof から作り、Tcl はそれを読む（手書きのずれを無くす）。
49. インフレは「世代」で持つ。カードは登場日（`cards.csv` の `release_day`）時点の年表のインフレ率 `era_pct` を焼き込み、強さに掛ける。古いカードは弱いまま残り、新しい SSR ほど強い。イベントの敵も開催日の `era_pct` で強くなる。未登場のカードはガチャ・ドロップに出ない。
50. 運営年表は `data/timeline.csv` の 1 本。kind は SERVICE_START / NEWS / EVENT / GACHA_RATEUP / INFLATION / PLAYER_DROP / ANNOUNCE_END / SERVICE_END / GIFT。イベントの開催日は EVENT 行から取り、`events.csv` の `start_day` は廃止した（#42 の置き換え）。処理済みの行は `timeline_cursor` で覚え、何日空けても 1 回ずつ処理する。
51. 確率アップ（GACHA_RATEUP）はその日から 7 日間、SSR が出るガチャの SSR の率を値（%）倍にする（200 = 2 倍、300 = 3 倍）。贈り物（GIFT）は石を全員に配る。
52. NPC の状態は保存しない。日数と NPC 番号から式で決める（成長・引退・イベントポイント）。乱数は掛け算・割り算を使わない 16bit ハッシュ（xor・シフト・足し算）で、用途ごとに離れた種（SALT_*）を使う。引退は PLAYER_DROP の行ごとの波で、割合はその行の値（%）。
53. ランキングは毎回 1000 人を 1 回なめて、上位 10 人か自分の前後を拾う（O(n)。並べ替えはしない）。#46 の静的な並びは使わなくなった。
54. 「みんなの動き」（レベルアップ・ランキング上昇・ボス撃破・SSR を引いた・ログイン）は 30 分（ゲーム内）ごとの枠から決定的に作る。同じ時刻なら何度見ても同じ。マイページのマーキーはお知らせと交互に流す。
55. マイページのメニュー 8 は「お知らせ」。最新のお知らせ 3 件、参加者数（引退していない NPC + 自分）、みんなの動き 4 件。バナーの優先順は イベント → 終了の告知（残り日数）→ 確率アップ → 最新のお知らせ。
56. サービス終了（SERVICE_END の日を過ぎた）後はマイページに入れない。タイトルに「思い出を見る」（カード一覧の閲覧だけ）と「思い出をリセット」（確認のうえ最初から）を出す。
57. 「つづきから」で入ったときの自動保存はすぐ書かず、マイページから別の画面へ移るときに書く（起動 3 秒の受け入れのため。ディスクへの書き込みを起動の時間から外す）。
58. BGM は FM 音源（OPLL, 7Ch/7Dh）3 チャンネル。曲は MML（`data/bgm/*.mml`）を `tools/mml.py` でバイト列にする。割り込みでは鳴らさず、メインループと待ちの中で毎フレーム進める（割り込みでバンクの窓を触らないため）。
59. ガチャの SR 確定チケットの率は SR 80 / SSR 20、ログインボーナス 6 日目の石は 300（`make sim` の受け入れに合わせた）。
60. イベントガチャは BOX ガチャ（`gacha.csv` の pool = box）にした。100 個入りの箱（N60 R30 SR9 SSR1、`n/r/sr/ssr` 欄を個数として使う）から引き、引いた分だけ減る。空になれば次の箱。箱の SSR は開催中のイベントの限定 SSR（無いイベントでは通常の SSR）。確率アップと 10 連の SR 確定は効かない。箱の残りは SaveData の `box_event / box_left[4] / box_no`（SAVE_VERSION 6）。値段は 1 回 200 石・10 連 1800 石で、1 箱引き切ると 18,000 石。
61. ガチャを難しくした。課金しない人の終了時の SSR の目標を、仕様の 3〜8 枚から 1〜3 枚に下げた（ユーザー判断）。天井は撤廃（データの pity を 0。2011 年頃の作法に合わせた）。SR 確定チケットは SR だけ（SSR 0%）。イベントの SSR はポイント報酬から外し、最終順位 10 位以内の報酬だけにした（6000pt の報酬は SR 確定チケットに、100 位以内は石 3000、1000 位以内は石 1000）。
62. `make sim` の模擬プレイヤーは、課金する人はイベント中に箱の SSR が出るまで石を買い足し、石油王・無敵モードは 3 箱目まで引き切る。所持枠が埋まったら合成で空けて引き続ける。
63. イベントの型は 3 つ（`events.csv` の kind）: 0 = 討伐（周回ボス）、1 = レイド、2 = バトル（対人戦）。当時の分け方（マラソン・レイド・PvP・GvG）に合わせた。年表の 7 本は 討伐・レイド・バトル・討伐・レイド・バトル・レイド。面の値は `event_stages.csv` の kind ごとの行（バトルの hp 欄は「相手の強さ＝自分の何 %」で、インフレを掛けない）。
64. レイド: ボスの HP は倒すまで残る（`raid_lv / raid_hp`）。1 回の攻撃は最大 5 ターン、力尽きたらそこまで。全力攻撃は攻撃 3 倍・AP 15。倒すと Lv が上がり最大 HP が Lv1 の半分ずつ増える。ポイント = 面の値 + 討伐ボーナス（Lv × 5）。救援依頼はボス 1 体に 1 回、同じギルドの辞めていない NPC が最大 3 人、最大 HP の 8〜15% ずつ削る。仲間がとどめを刺したら討伐ボーナスの半分が入る。
65. バトル: 相手は NPC。戦うたびに `pvp_seed` で顔ぶれが替わる。自分の戦力（デッキの攻撃 + 防御、特効込み）× 75〜135% と、相手の戦力（自分の 80 / 100 / 120%）を比べる。勝てば面のポイント、負けても 1/5。
66. ギルド: 初めてマイページに来たとき 16 ギルドのどれかに入る（`guild` 1..16）。NPC は生成時からどこかのギルドにいる（`NpcRec.guild`）。
67. ギルド対抗戦: 年表の GUILDWAR 行（140 日目と 215 日目）から 7 日間、1 日 2 回（12:00 と 21:00 から 1 時間, ゲーム内）の計 14 戦。組み合わせは「ギルド番号 xor k」（k は戦ごとに 1..15）で全ギルドが 1 対 1。ギルドの点 = 辞めていない所属 NPC の戦力の合計 / 64 × 80〜120%。自分は戦の時間中に攻撃（AP 10、1 回 ≒ 仲間 1 人ぶん、コンボで +5% ずつ）と応援（1 戦に 1 回、ギルドの点 +3%）。終わった戦はマイページに入ったときにまとめて結果を出す。1 勝ごとに石 100、終了時の順位で 1 位 SSR・3 位まで SR・8 位まで石 1000・それ以外は石 300。
